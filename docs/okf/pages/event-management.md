# What it does

A runner of an event is an admin, or an organizer the event names; the backend holds the list, and `useEventRunner` in `next/src/hooks/event-runner.ts` reads it for a page. Anyone else who opens a run page reads "You Don't Run This Event". The steps below take a runner from nothing to a finished event; making a league stays an admin's. Each step names the page, what the admin does there, and the route the store calls. The backend owns every rule the routes apply.

**1. The league.** On `/leagues`, "New league" takes a name, a short name, the kind (GNL, KOTH, custom), what an entrant is (solo players, pre-made teams, drafted teams) and a page link. It writes `POST /leagues`. A league that exists is reused: it is what repeats.

**2a. A cup, the short way.** "Create cup" on `/events` opens `/events/new/cup`, five steps for an organizer's evening cup: Basics (the name, the day, the start time, the game, 1v1 or a team cup of 2v2, 3v3 or 4v4, which writes `team_size` and the team entrant kind, custom game and FFA still to come, and a description), Format (single elimination, double elimination, a placement bracket or Swiss, which runs "A set number of rounds", each round paired on the table and drawn by itself once the round before has every result, or "Everyone plays everyone", a full league written as a round robin, "Then" no playoff, "Top 4" or "Top 8", a single elimination the last result seeds and draws, with the match for third place, a match for third place, a grand final reset, or on a placement bracket "A player stops after" 1 loss, 2 losses, 3 losses or "Every place", which writes `placement_lives`, "Hide seeds from players", off by default, which shows the seed numbers to the organizers and admins alone, and the best-of: "Early rounds" Bo1, Bo3 or Bo5, then each part of the bracket counted back from the end, "Quarterfinals", "Semifinals" and "Final" in a single elimination, "Upper semifinal", "Upper final", "Lower semifinal", "Lower final" and "Grand final" in a double one, "Last round" and "Final" in a placement bracket, each "Same" as the early rounds or a best-of of its own, `BestOfPlan`), Maps (the pool the players veto from, `MapPoolPicker`: "Use the 1v1 ladder pool" (or the 2v2 or 4v4 one on a team cup) first imports the ladder maps the app lacks (`POST /maps/ladder-import`), then adds the whole pool and says how many maps it added, "Copy from a cup" takes the pool of a cup the reader runs or any other cup, "Add a map" searches the app's maps, the cup's own mode first, each with the modes it is played as, and each map moves up or down or leaves on its own row; the step is left only once the pool holds the longest series, "A Bo5 needs at least 5 maps in the pool"), Sign-ups ("Only eligible players can sign up", on by default, with "The battle tag must be linked to Battle.net too" under it, off by default, the MMR from and to, the games at least over all races, "A race counts from" 20 lifetime games, so the best MMR of the races a player has really played is checked, who may sign up, which is members only while the Battle.net switch is on, the minimum and the maximum players, check-in, publish now, open sign-ups now) and a review. "Create cup" writes `POST /events` with the cup, `veto_by_best_of`, the pool as `map_ids` and its one elimination stage with `best_of_by_round`, played immediately, and no end date, so the cup ends on its finish or its last result and never at midnight; it lands on the run page. The run page reads the draw, the table and the entrants fresh after every write, past the edge and the browser cache. `next/src/helpers/cup-wizard.mjs` builds the body and `next/src/helpers/best-of-plan.mjs` the best-of plan, its line ("Bo1 early · upper final Bo3 · grand final Bo5") and the pool rule.

**2. The event.** On the league page, "New event" opens `/events/new` with the league preset. The wizard makes a signup-only event; a cup is made with Create cup, and a GNL season and a KOTH night elsewhere. Its steps:

- Basics: the league, the name, the kind, "Part of" (an event of the same league that this one feeds, for a qualifier; archived KOTH nights are not offered), the region, the start and end date, the start time, the round end zone, the description, a page link and a stream link. The round end zone is an IANA name from the browser's own list, with UTC always offered; a round of an event that names none ends at midnight where the reader is.
- Entrants: who may sign up (Discord members with an account, or anyone with a battle tag; members only while the Battle.net switch is on), "Only eligible players can sign up", on by default, which refuses a signup or a hand-add without a battle tag W3Champions rates inside the bounds, and under it "The battle tag must be linked to Battle.net too", off by default, what an entrant is (solo players or pre-made teams), the series per fixture on a team event, the entrant cap, the MMR minimum and maximum, the recent games floor with how many of the newest W3C seasons it counts over, and the check-in switch with the days before a round it opens and the early check-in switch, which lets a player check in for any round that has not ended.
- Stages, one or more, each with a name, a format (round robin, single elimination, double elimination, Swiss, KOTH, free for all), a best-of (1, 3, 5, 7), a map rule (veto, loser picks, host picks, fixed map), the format's own fields (players per lobby and the points each place pays for a free for all; the round count for Swiss; the series each entrant plays per round, the group size and the entrants each group advances for a round robin), the scheduling mode (an admin sets the time, the two sides agree, played straight away), the count of entrants who advance, and whether they advance by themselves. A signup-only event skips this step.
- Divisions: none, or two to six, each named. The MMR bounds are cut later on the entrants page.
- Review, with an edit link back to each step.

A step with a problem cannot be left: no league or no name, an end before the start, a cap under two, check-in on with no days, a games count over fewer than one W3C season, no stage, an even best-of, a lobby under two seats, a group under two seats, a group that advances nobody, or one division. "Create event" writes `POST /events` with the stages in the same body, so no event exists without its stages, then `PUT /events/{id}/divisions` when divisions were asked for, and lands on the event page. When the event was written but the divisions write failed, the event page says so.

**3. The entrants.** Members enter on the event page; see [the public side](leagues-and-events.md). On `/events/:id/entrants` an admin also enters any player or team by hand, whether the signups stand open or not: "Add entrant" takes a player or a team and the race, and writes `POST /events/{id}/entrants/admin`. A row's menu offers "Check in" (`POST /events/{id}/entrants/{entrant_id}/checkin`), "Remove" (`DELETE /events/{id}/entrants/{entrant_id}`) and, for a player, "Ban player" (`PUT /users/{id}/ban`), which warns on every entrant row of every event and refuses no signup.

**4. The divisions.** On the entrants page, the strip over the table cuts the entrants by MMR; it draws one dot per entrant row and counts players, so a player on two races is two dots and one count. The admin picks the count (two to five), presses "Even split" for quantile cuts or drags the cuts, and presses "Save divisions", which writes the bands with their names and bounds through `PUT /events/{id}/divisions` and clears every placement made by hand. "Assign from MMR" writes `POST /events/{id}/divisions/assign`, which cuts the entrants into the stored divisions from the MMR of their signup race. A KOTH night takes no division write from this page, because those writes rebuild its brackets: it draws no MMR strip, none of these four controls and no move, pin or Remove in a row's menu, because the run page removes a player under the night's forfeit rules, and one line points at the night's run page, which moves its bounds in place and places every entrant. A row's menu moves one entrant into another division and marks it placed by hand (`PUT /events/{id}/entrants/{entrant_id}` with `division_id` and `manual_placement`); the pin on the row toggles that mark, so a reassign leaves a pinned entrant where it is.

**5. The seeds.** On the same page, the admin picks the stage when the event has more than one; a chip beside it reads "Locked" or "Unlocked". "Seed by MMR", "Shuffle", or "Seed from the previous stage" on a stage that has one each write `PUT /events/{id}/stages/{stage_id}/seeds` with a `source`; an entrant placed by hand, marked with the pin titled "Placed by hand", keeps its seed through a reseed by MMR or shuffle. Dragging a row inside its division, or its move up and move down buttons, writes the same route with an order of entrant ids, which is the manual source. One toggle locks and unlocks: "Lock seeds" writes `POST /events/{id}/stages/{stage_id}/seeds/lock` and "Unlock seeds" writes `DELETE /events/{id}/stages/{stage_id}/seeds/lock`. A locked stage takes no reseed and no reorder, shows each seed's source, and the public page starts showing the seeds, unless the event hides them. A stage that holds series, known from the rounds the event read lists, refuses the reseed and the unlock too; the disabled buttons point at one caption with the API's refusal, "The seeds of this stage are locked" or "The stage holds series; take its draw back first", and `seedLock` in `next/src/helpers/entrants.mjs` answers it. A KOTH night takes no seed write either, because a seed orders the queue the night is running: it draws none of the seed controls and no drag handle, and the same line points at the run page.

**4a. A cup's divisions and seeds.** A cup does neither on the entrants page. Its Sign-ups step in Create cup holds "Split the players into divisions", off by default; a cup made without it shows no division anywhere, its run page included. A cup made with it gets a Divisions panel on its run page's Participants tab (`CupDivisionsPanel`): the count, the MMR strip with "Even split", and "Save and place the players", which writes `PUT /events/{id}/divisions` and `POST /events/{id}/divisions/assign` in one go; then one card per division, and "Not in a division" while a player stands in none, each player with "Move to …" (`PUT /events/{id}/entrants/{entrant_id}`), which pins it, and "Let the MMR place this player" to unpin. Its first stage's seeds sit beside the draw on the Draw tab (`CupSeedsPanel`): the players in seed order, "By MMR" and "Shuffle", and a manual order: each player's seed is a plain number field, committed with Enter or on leaving it, an empty or non-numeric entry putting the seed back, and a row drags to a new place inside its division (`placedOrder`); the pin at the end of a row keeps that seed through "By MMR" and "Shuffle" (`PUT /events/{id}/entrants/{entrant_id}/pins`), and a finished cup still shows its pins; a cup with divisions has one block per division, each seeding that division alone with `division_id`. The Divisions panel only reads once the stage is drawn; the Seeds sidebar stays open after the draw, and every change there writes `PUT /events/{id}/stages/{stage_id}/seeds/redraw`, which draws the bracket again from the new seeds, and reads the draw back. While the stage's series hold results, the change asks first, "Draw the bracket again?", and "Delete the results and redraw" sends it with `?confirm=true`. A finished cup or round only reads its seeds. The Generate dialog of a cup without divisions names no division. `next/src/helpers/cup-divisions.mjs` groups the players and builds the seed writes.

**4b. A cup over rounds.** Create cup's Basics step asks "How it is played": "One evening", the default, or "Several rounds", each round a cup of its own with the same format. "Several rounds" asks for the number of rounds, 2 to 12, and a day and time for each after the first, a week apart from the first round's day and start time until the organizer changes one; a round must start after the one before. A step "Points" sits before the review: the points each place of a round pays, prefilled 10, 8, 6, 5, 4, 3, 2, 1, with "Add a place", "Remove the last place" and a reset, and the review lists the rounds and the points. The cup is written with `legs`, one start a round, and `points_by_place`, and its cup-wide check-in off; the Sign-ups step says players check in for each round instead. On the run page the Draw tab holds the rounds bar (`CupRoundsBar`) under the evening panel: one button a round with its day and its state, "Check-in", "Playing" or "Finished", opening on the first round not finished. Before the round's draw it counts the players checked in, lists every player as a button that checks them in or out (`POST` and `DELETE /events/{id}/legs/{leg_id}/checkins` with the `entrant_id`), and offers "Check everyone in" (`POST /events/{id}/legs/{leg_id}/checkins/everyone`). The stage tabs, the Seeds sidebar and the Generate dialog read the round's own stages and the players checked in for it. Once every series of the round's last stage has a result, "Finish Round n" writes `POST /events/{id}/legs/{leg_id}/finish` and reads the entrants again, whose seeds the finish clears; a finished round reads "Reopen the round" (`DELETE` on the same path), keeps its draw, and offers the next round. The cup's own "Finish" shows once every round is finished, and pays the overall table. The Results tab leads with the overall table (`CupOverallTable`, `GET /events/{id}/overall`, read fresh and again after a round's finish), a round picker for the matches below it, and a podium placed on the overall table. A format edit on the run page sends one round's stages, which every round takes. `next/src/helpers/cup-wizard.mjs` builds the rounds and the points, and `next/src/helpers/cup-rounds.mjs` picks a round's stages, field and state.

**4c. A recurring cup.** Under the run page's header, a cup that has a start offers "Repeat this cup" (`RepeatCupDialog`): the name, prefilled with the cup's name without a trailing number or date, the day of the week and its start time, prefilled from the cup in the viewer's zone, "How often", every week or the first, second, third, fourth or last of the month, and an optional last day, with the rule read back in one line, "Every Friday at 21:00, in Europe/Berlin". "Repeat" writes `POST /events/{id}/recurrence` and opens the recurring cup's page. A cup made from a rule reads "Part of {name}" there instead, a link to that page. The page `/events/recurring/:id` (`RecurringCupView`) reads `GET /cup-recurrences/{id}`: the rule's line, "Coming days", the next eight days, each with the cup made on it or "Not created yet", and "Cups so far", newest first with their state. A runner of the latest cup gets "Create" on each day not created yet, which writes `POST /cup-recurrences/{id}/occurrences` and reads the page again, "Run it" on each cup, and "Stop repeating", which asks once, writes `DELETE /cup-recurrences/{id}` and keeps every cup. `next/src/helpers/cup-recurrence.mjs` reads the rule and suggests one from a cup.

**6. The run.** `/events/:id/admin` reads, on every event but a GNL season, as the same three tabs as the event page, "Draw", "Participants" and "Results", with the tab in the address. "Draw" opens with a bar (`CupConsole` part `evening`): the players still in, or on a team cup the teams, and how many checked in, against the minimum and the maximum, and "Cancel the cup"; on a cup, "Format and maps" (`CupFormatCard`), the best-of line and the pool, with "Edit" until the bracket is drawn, which writes the pool with `PUT /events/{id}/maps` and the stage with `PUT /events/{id}/stages`, the growing side first so the pool always holds the longest series; below the minimum, before the draw, a warning with "Move the start", which opens on the stored start in the runner's zone and writes `PUT /events/{id}` with the new day and time and no end date, a changed day alone keeping the time of day (`moveStartBody` in `next/src/helpers/events-page.mjs`), and "Cancel the cup" (`POST /events/{id}/cancel`, after one red confirm). Then the stage's buttons and its drawing; a bracket draws no table under it. "Participants" (part `people`) is the "Players" card, or on a team cup the "Teams" card: each team on its row with its state ("Complete", "Waiting for <player> to accept" while one invite is open, "Waiting for 2 of 3 to accept" for more, "1 player missing"), check-in once it is complete and Remove, its players under it, the captain marked, each with a swap icon until the team has played (`POST /events/{id}/cup-teams/{team_id}/members/{user_id}/replace`), after which the page reads the teams again so the draw names the new player, and the players invited who have not answered; "Add team" enters a whole team by hand, a name, a captain and the other players (`POST /events/{id}/cup-teams/admin`), and "Remove n incomplete teams" takes out before the draw the teams still short of players, since the draw refuses them. On a 1v1 cup the card lists every player on a row of their own, in seed order once seeded, with "Check in" and "Remove" (after one confirm naming them) until the bracket is drawn, and "Add player", which picks any player who is not in and their race and writes `POST /events/{id}/entrants/admin`; after the draw, "Withdraw" on the row of every player still in, after a red confirm that says they forfeit every open match and their opponents go through, which writes `POST /events/{id}/entrants/{entrant_id}/withdraw` and reads the entrants and the draw again, and "Swap" on the row of a player who has played no match (`playedEntrants` in `next/src/helpers/stage-view.mjs`), which opens the same picker as "Swap <name>", says the new player takes the seed and the matches and a begun veto starts over, and writes `POST /events/{id}/entrants/{entrant_id}/replace`, then reads the entrants and the draw again; "Seed players" to the entrants page; the "Waitlist" under the players, first come first, with "Add to the cup" before the draw (`POST /events/{id}/entrants/{entrant_id}/admit`, past the maximum if need be) and, after it, "Swap in", which picks a player who has not played and writes the replace with the waiting player; a waiting team comes in only before the draw; "Remove n no-shows", which deletes the entrants that did not check in, so the draw holds the ones who did; then the "Organizers" card, where a runner adds a co-organizer by Discord id and name (`POST /events/{id}/organizers`) or removes one. "Results" is the event page's results tab, where a click on a match opens its result dialog. An event of more than one stage picks the stage over the draw and over the results. A GNL season keeps one page: one tab per stage with the same stage view the public page shows. The buttons a stage takes:

- "Undo the draw", in the error colour, while the stage holds series and the event is not finished, asks once in a red confirm that names what goes, "The bracket and its 7 series are deleted, with 1 result, their map vetoes and replays", and writes `DELETE /events/{id}/stages/{stage_id}/series`. When the API answers 409 because series of the stage hold results, the same dialog names the count from the error ("3 series of this stage hold results. Undoing the draw deletes them.") and its button reads "Delete 3 results", which sends the call again with `confirm=true`; Cancel or closing the dialog forgets the count. The page then reads the event, the entrants and the stage again, so "Add player", "Remove", "Seed players" and "Generate" are back. `playedCount` counts the results the confirm names, and `undrawResults` in `next/src/helpers/stage-view.mjs` reads the count from the 409.
- "Generate", while the stage holds no series, writes `POST /events/{id}/stages/{stage_id}/generate`; the confirm names the seed source and the field per division, with the byes. A Swiss stage has "Draw the next round" instead, `POST /events/{id}/stages/{stage_id}/rounds`, disabled while a series of the round before carries no result and once every round is drawn.
- A series box opens the result dialog: the winner of each game, and the winners make the score. "Save result" writes `PUT /cup-series/{id}` with the two scores. "Walkover" and "Forfeit" take the side that gets the series and write `PUT /cup-series/{id}/result-kind`. "Reopen" writes the same route with cleared scores; when the engine refuses because a later series already carries a result, the page asks once more and retries with `?force=true`.
- A free for all lobby opens the places dialog instead: the admin drags the seats or types the places, and "Save places" writes `PUT /cup-series/{id}/places`. Before a lobby is played, "Move" sends one entrant to another lobby of the same round through `PUT /cup-series/{id}/sides` on both lobbies.
- On a team event, the players each side fields are named on the series page; see [fixtures and series](fixtures-and-series.md).
- "Advance", once every series of the stage carries a result and only on a stage another stage follows, writes `POST /events/{id}/stages/{stage_id}/advance`; the confirm lists the entrants who move on, the top of each division's table. A cup plays one stage, so its run page never shows it; "Finish" ends it.

**7. The awards.** On the last stage's tab, "Finish" writes `POST /events/{id}/finish`. The confirm lists every entrant the close awards and the place it takes (Champion, Runner-up, Third, Placed n), because the close freezes that stage's table into the award rows. Finishing again rewrites the places from the table as it stands. The close also stamps the event closed, so it reads finished whatever results are missing; on a closed event the tab carries "Reopen", which writes `POST /events/{id}/reopen` and takes the stamp and the places back. The event page then carries each place on the entrant's row, and a first place reaches the player page's trophy shelf.

**KOTH nights.** A night is one event of the KOTH league, so the league, the wizard and the entrants page hold for it. `/koth` lists the nights newest first, 25 a page, and each name opens its own run page `/koth/nights/:id`, where the admin sets the night's settings and its bracket bounds, pairs every series by hand, edits the line and closes the night with `POST /koth/nights/{id}/close`; see [KOTH](koth.md). "New event" on `/koth` opens the "New KOTH Event" dialog, which takes the start time and the three MMR bounds the brackets open at, prefilled from the night before; "Open the event" writes `POST /koth/nights` and lands on the run page. A night is not run on the stage engine, so `/events/:id/admin` of a night sends the admin on to its run page.

# Rules

- The stage view, the standings order and the third-place box: [shared components](../concepts/shared-components.md).
- A name inside a dialog is plain text: [the player panel opens only on drafting pages](../decisions/player-panel-drafting-only.md).
- The entrants list is a grouped table: [one grouped table component](../decisions/grouped-table.md).
- A write returns the backend's answer and the page reads again; nothing is updated ahead of the answer: [stores](../concepts/stores.md).
- Reads are open and writes are admin, so the page hides the controls a member cannot use: [the backend contract](../concepts/backend-contract.md).
